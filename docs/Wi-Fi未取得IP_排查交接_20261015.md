## 仍缺哪段证据

需要在实际AP/网关/DHCP服务所在接口记录同一轮请求和回复。本机普通用户无法打开BPF，sudo-n tcpdump要求系统密码；没有抓包文件，也没有更改系统权限。电脑当前租约存在不证明相框这台客户端可以拿到租约。

在有权限的网络设备上，选择相框所在的实际LAN/无线接口，用此过滤仅记录该相框的DHCP（chaddr）：

```sh
tcpdump -i <实际接口> -n -s 0 -w bloom-e394-dhcp.pcap 'udp and (port 67 or port 68) and udp[36:4] = 0x94a990f4 and udp[40:2] = 0xe394'
```

相框MAC：94:a9:90:f4:e3:94。接口若保留VLAN封装，应按实际接口调整过滤；不要把过滤无结果直接当作没有报文。

| 观测点 | 需要确认的内容 | 能缩小的范围 |
|---|---|---|
| AP接收/解密后 | 是否见到该MAC的完整DISCOVER，与设备端字段一致 | 无线发送/解密/转发，或后面的DHCP链路 |
| DHCP服务入口 | 是否收到对应事务ID与chaddr | AP到服务之间的桥接/VLAN/转发 |
| DHCP服务处理 | 是否发OFFER，或有拒绝/地址池/策略记录 | 服务处理或客户端参数兼容 |
| AP回传接口 | OFFER是否真实返回该无线站点/广播域 | 回复回程与相框接收之间 |

取得同一事务的成对记录后再修对应环节；当前证据不足以认定路由器或密码有错。
