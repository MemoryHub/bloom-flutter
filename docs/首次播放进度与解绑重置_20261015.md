# 首次播放进度与解绑重置（2026-10-15）

本轮按用户要求：已有照片的账号配对完成后，由用户点击“完成并开始播放”，立刻收到准备反馈；实际照片上屏后才宣布完成。保留手机登录、账号图库和供图者图库。用户已休息，今晚不再提问，明早进行完整真机验收。

## 用户流程

1. 相框二维码或附近设备：先实际 BLE Security1 连接并核对 hello 的设备身份，成功后取名；取名不用相框先连 Wi-Fi。
2. 选择 Wi-Fi 并完成真实账号归属；服务端仅检查本人的有效图片，不以其他账号图片代替。
3. 账号已有照片：第4步显示已有照片引导，“完成并开始播放”进入独立准备页；账号无照片仍显示“添加第一张照片 / 稍后添加”。
4. 准备页按相框实际报告展示四节点：获取轮播计划、准备第一张照片、下载第一张照片、刷新相框屏幕。未接收命令时明确等待，不由定时器自动推进或伪造百分比；缓存已就绪时允许跳过不需要的阶段。
5. 点击“后台运行”返回首页，任务留在服务端和设备，手机不会发取消命令。首页保留查看入口；App退出、离线、重开后恢复最近真实进度，切换账号不泄露上一账号任务。
6. 相框实际完成波形后上报 succeeded/completed，准备页才显示“完成”，点击返回首页。准备失败提供重试；最近任务完成并关闭后，不重新展示同相框旧失败提示。

## 三端实现

- 后端迁移022_first_playback：first_playback_capable、awaiting_first_playback、start_playback任务及阶段/字节字段。只有App和设备均声明支持新协议时，新绑定有照片才等待开始按钮；旧固件或旧App仍按原流程，避免服务端升级后旧设备卡住。开始任务需要本机主人权限、可用照片、OTA/配置互斥，32位随机请求ID防止网络重试重复创建。设备身份鉴权的report才可推进/完成；阶段不回退。重置并重新绑定的任务历史不会混入新流程。
- App FramePlaybackController和BloomFramePlaybackPage：账号隔离、请求ID与配对轮次持久化、旧响应隔离、实时节点动画、小屏滚动和固定操作区、失败状态停止动画；向导和准备页隐藏重复首页入口。版本1.0.50+7054。
- 固件 bloom_playback：CRC保护的原子NVS任务记录、断电恢复、真实刷屏完成先落盘再上报；丢HTTP回执只重报，避免重复波形。首张准备10分钟失败后保留可重报终态，不永久在线空转。只有显式首次请求绕过普通计划开始时间，原轮播作息/缓存准点行为保持原规则。先当前方向首图实际显示和回执，再补同图另一方向，随后预取后续图片。通用固件20261015-first-playback-v1B/code2026101500。

## 解绑行为
