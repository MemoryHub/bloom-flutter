# Bloom 真机测试手册（截至2026-10-15）

## 先确认当前状态

- iOS、Android均为1.0.52+7056；相框E394当前1515/v14工程诊断。
- 两手机使用同一个主人账号；保留App数据、已上传照片和原保存网络。
- 当前只用同一个公司Wi-Fi，不要求热点、换路由器或做换网对照。
- 当前“已关联但未取得IP”尚未修复，暂停反复重连。与添加成功相关的用例列为阻塞，不预填通过。
- 本轮先测试当前已绑定相框；当前不执行解绑/重置/新机初始化脚本，也不删除现有唯一网络。后面的这些用例仅为后续完整验收计划。

## 建议顺序

先做A的轮播与转向，再做B的浏览、扫描及释放；取得IP的问题解决后再做C；最后单独安排D的重置/首次开箱、新设备与OTA验收。A有异常时先记录并停止网络操作。

## A．最优先：轮播与横竖切换

| 编号 | 操作步骤 | 应看到的结果 | 当前记录 |
|---|---|---|---|
| A1 正常轮播 | 按现有作息和间隔，连续观察3个实际换图点，记下时间 | 按原计划换图，无停图、循环重启或连续空刷 | 待真机 |
| A2 四姿态 | 同一张照片依次摆正竖、反竖、正横、反横，每次稳定超过8秒；刚刷完先等30秒保护期结束 | 方向正确，切当前照片的缓存方向，不额外换照片 | 待真机 |
| A3 快速翻动 | 30秒内快速来回翻转，然后固定一个姿态超过8秒 | 不连续乱刷，最终稳定方向得到正确画面 | 待真机 |
| A4 临近换图转向 | 在换图准备点/换图点附近改变方向，记录画面和时间 | 按原合并逻辑完成，不双刷、错图或多延后一轮 | 待真机 |
| A5 扫描与显示冲突 | 在原换图点附近点添加、扫描网络，或扫描期间稳定转向 | 轮播/转向优先；网络操作可被中断并明确提示，不假报成功 | 待真机 |
| A6 独立供电 | 电脑USB拔下，改独立充电器或电池，重复A1—A3及B3扫描 | 自动轻睡环境下仍可发现、扫描、轮播和转向 | 待真机；USB测试不替代本项 |
| A7 离线缓存 | 仅在相框自然处于断网且已有缓存时，观察到原换图点并稳定转向 | 缓存范围内显示和转向继续，恢复联网后再更新计划 | 待真机；不要求关闭公司路由器 |

## B．当前可以检查：操作入口、扫描、失败与释放

先单独用iPhone；确认已退出操作后再用Android重复，不要一开始同时抢连接。

| 编号 | 操作步骤 | 应看到的结果 | 当前记录 |
|---|---|---|---|
| B1 只浏览 | 打开App→设备列表→E394详情→Wi-Fi，只查看 | 不出现主动连接相框进度，不因浏览刷屏；页面可能是云端/缓存摘要 | 待触屏验收；内部连接是否发生需日志核对 |
| B2 独立入口 | 设备详情→Wi-Fi→添加 | 加载连接相框和主人验证，然后进入独立Wi-Fi列表；没有取名、第一张照片和四步向导 | iOS已确认能到列表；Android待触屏验收 |
| B3 扫描列表 | 手机靠近，等待扫描，查看各页/长网络名 | 网络列表可读；长回复不截断、不误报身份失败 | 恢复后电脑实际3501ms/9AP与全分页通过 |
| B4 首次授权 | 另一台已安装新版的主人手机首次管理时保持手机联网 | 正常取得该账号该设备的授权；不是相框必须先联网 | 主人授权实物通过；双手机触屏待验 |
| B5 已知失败结果 | 查看已有失败页即可，当前不用再重复连接 | 顶部“连接未完成”，提示未取得IP；无假成功，原保存网络仍在，可重新选择 | 当前公司网真实失败已复现，不能记为添加通过 |
| B6 取消/后台 | 扫描中取消/返回；另一轮进入后台 | 释放连接，其他手机随后可管理；不保存未成功候选，原网络保留 | 电脑正常释放已过；手机各出口待验 |
| B7 蓝牙不可用 | 在明确点击添加前关闭手机蓝牙，再点添加；测试后恢复蓝牙 | 清楚提示蓝牙不可用，可返回；不伪造“被占用”或修改网络列表 | 待真机 |
| B8 超时释放 | 进入管理页后停留超过会话时限，再操作 | 提示重新连接或已释放，不能永久占用相框 | 待真机 |
| B9 双手机占用 | 只做连接/扫描：iOS占用时Android搜索；iOS退出后Android再连接 | 显示真实占用、不能抢连；释放后可继续 | 待双手机真机 |
| B10 重新上电 | 相框空闲时重新供电，再做B2/B3 | 原身份、主人授权和保存网络恢复，仍能扫描，后续轮播正常 | 当前恢复启动及认证/扫描已过；用户触屏/显示待验 |

## C．当前阻塞：取得IP之后再进行的网络用例

以下不用现在反复尝试，待同公司网络真实拿到IP后依次执行。先iOS通过，再Android重复。

| 编号 | 操作步骤 | 通过条件 |
|---|---|---|
| C1 添加成功 | 详情→Wi-Fi→添加→选同一公司网→填密码→连接→完成→返回已保存网络 | 真实取得IP且保存成功；App明确成功，返回后能看到该网络；不得用关联成功代替 |
| C2 重复管理 | 完成C1后退出，再次进入添加并扫描；刷屏/转向后再重复 | 不只冷启动有效，关闭/恢复射频后仍能扫描和管理 |
| C3 错密码保护 | 在正常网络链路已确认后，输入错误密码；再重新选择并填正确密码 | 明确失败，不覆盖原网；输入和重试入口可用；正确密码最后成功 |
| C4 已授权手机无互联网 | 确认手机已缓存授权后，使手机没有互联网但保留蓝牙，读取列表并管理网络 | 不因无法请求服务端而拒绝已授权的本地操作；新授权仍需手机联网 |
| C5 删除备用网 | 只有已有备用保存网络时才确认删除一个非当前网络 | 先验证再删除，回执后移除；当前连接与轮播保留 |
| C6 删除当前网 | 已有另一个可用保存网络且可恢复后，删除当前网络 | 不再重连被删网，尝试其他保存网；实际结果才更新列表 |
| C7 删除最后一个 | 只在重新添加已反复成功后单独安排，删除最后一网 | 蓝牙仍可发现，可重新添加网络，无需中键；云照片保留 |
| C8 账号隔离 | 换成非主人测试账号，再尝试管理原主人的设备 | 不能沿用原主人凭证改网络；不扩大照片访问权限 |

当前仅保存1个旧网络，C5—C7没有满足前置条件，保持不执行。备用网络是后续删除场景的条件，不是当前排查的换网要求。

## D．后续单独安排：首次开箱、首播、解绑与新设备

| 编号 | 操作步骤 | 通过条件 |
|---|---|---|
| D1 正常解绑并重置 | 网络问题解决、确定安排该项后，从设备详情正常解绑；等待真实设备回执 | 相框清私人缓存、网络与旧授权，回专属欢迎页/二维码；云端照片保留。当前仍走云任务，离线可能等待 |
| D2 扫码首次添加 | D1真正完成后，在设备页扫实屏二维码 | 识别这台相框并真实连接/核验，然后进入取名；不回泛搜页，扫码按钮为绿色填充 |
| D3 取名与配网 | 输入名字→下一步→网络列表→连接同一公司网 | 取名不要求相框已经联网；网络阶段真实成功后进入最后一步 |
| D4 已有照片首播 | 使用当前有照片的主人账号，点“完成并开始播放” | 显示已有照片提示；进入计划→首图准备→下载→刷屏的实际进度，当前步骤高亮 |
| D5 后台与恢复 | 首播进度中点后台运行，回首页；关闭/重新打开App后继续查看 | 对应任务可继续看，旧轮次/旧账号的结果不会冒入当前任务 |
| D6 首播完成 | 等相框实际显示第一张照片，再看手机并点完成 | 真实刷新结束后才显示完成按钮，点后进入首页；不是仅下载完成就报完成 |
| D7 首播失败/重试 | 如首播出现失败，记下原文后点击重试 | 明确失败阶段，动画不假推进；重试不会重复启动已成功的旧任务 |
| D8 无照片账号 | 仅隔离空图库账号/新设备测试 | 继续上传第一张照片引导；不删除现有主人照片来模拟 |
| D9 第二台新设备 | 以后明确“这是新设备”时按项目固定初始化流程执行 | 核板型/MAC、完整备份、生成独立身份/二维码/欢迎资源，实屏可扫码；现役E394不当新机重造身份 |

新机脚本：tools/initialize_new_frame.sh及.py；固定文档：docs/新设备初始化烧录固定流程_20261014.md。第二台裸板bootstrap尚未实测；当前1515工程诊断不作为稳定制造默认。

## E．当前不能按“即时唤醒”验收的功能

OTA、朝向/轮播/作息保存后同步、正常解绑的通用蓝牙“现在检查服务器”入口尚未接入。这些仍走原云端机制，不期待点击后立即执行。OTA签包不是发布，本轮未发布OTA；真实失败回滚另行安排，不在当前手机网络测试中执行。

整板平均待机电流、一次网络管理/换图能量需要独立供电仪表测试。当前没有新版常驻BLE的实际mA或续航结论。
