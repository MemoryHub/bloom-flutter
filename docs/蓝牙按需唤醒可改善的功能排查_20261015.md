# 蓝牙按需连接可改善的等待环节（代码排查，未冒称已实现）

原则：查看 App/设备列表/详情/设置、后台定时同步均不连接 BLE；只有用户提交操作后显示连接进度。蓝牙仅负责现场主人验证与触发工作，云端仍负责账号权限、权威排程、照片准备与 OTA 签名。网络必须真正取得 IP，屏幕必须真正完成刷新，再报告对应成功。

| 操作 | 当前代码行为 | 可改善的行为 | 约束与本轮状态 |
|---|---|---|---|
| 添加/删除 Wi-Fi | 新版已用按按钮触发的本地管理 | 连接主人授权后扫描/连接/删除，无需等待下一计划点 | 本轮已实现；不能开 App 就连，失败保旧网 |
| 开始 OTA | 云端建更新任务，相框维护阶段再领取；页面提示等待联网 | 点开始后建任务，再经 BLE 请求安全联网检查 OTA | 尚未接入；仍需发布签名包、真实回滚门槛、足够维护窗口，不能打断正在刷屏/临近换图 |
| OTA 下载中取消 | 云端标记取消，相框通过任务进度拉到状态 | 明确取消可经 BLE 提示设备尽快联网确认取消 | 尚未接入；安装/启动验证阶段不可取消，不能伪报立即停止 |
| 轮播/推荐切换、间隔及生效窗口 | 手机云端保存成功，相框下次联网读取设置 | 保存后自动按用户这次明确提交尝试 BLE 同步，并展示已保存/相框已应用两个状态 | 尚未接入；读取页面不连，不凭云端保存推断设备已应用；保留计划绝对时间与原缓存策略 |
| 自动朝向/锁定朝向 | 云端保存，设备下一周期读取；App仍残留“轻按中键”提示 | 提交后按需同步方向设置，核回执后说明已生效 | 尚未接入；不改原四姿态/8秒/快翻保护，不隐含强刷，后续去掉按中键文案 |
| 展示来源与艺术作品集 | 云端修改内容选择，后续权威计划更新，设备周期下载 | 用户明确保存或选“同步到相框”时请求联网拉新计划/准备缓存 | 尚未接入；云端 RAW 准备有耗时，“联网已成功”不等于“新图已显示” |
| 主动立即刷新/开始播放重试 | 首次已有照片有真实首播任务；日常无统一即时刷新入口 | 显式按钮建立真实播放任务，BLE只触发拉取，复用时间轴 | 日常入口尚未新增；不能复用首次绑定状态冒充日常刷新，不能承诺屏幕瞬间完成 |
| 正常解绑并重置 | 持久云任务，等待设备领取；设备擦私人缓存、刷欢迎并回执后才清归属 | 点确认后先安全安装/验证本地授权，建重置任务，经 BLE 请求立即检查 | 尚未接入；确保主人授权撤销顺序、失败不能提前删绑定或云照片，刷屏结束前仍需等待 |
| 查看实时设备状态/本地网络详情 | 页面主要是云端/缓存摘要，可能滞后 | 可提供明确“读取相框实时状态”操作，BLE验证后读取状态 | 尚未新增；普通下拉刷新云数据和查看页面不连；云端 last_seen 与 BLE可达不能混为同一种在线 |
| 新照片上传、相册调整 | 云端上传、分析/处理并影响计划 | 用户显式“送到相框”后才触发联网拉取，不对每次上传自动唤醒 | 不能靠蓝牙跳过云端处理或自动推翻轮播；本轮未新增 |
| 设备名称/共享邀请/账号照片管理 | 手机及云端即可完成的操作 | 保持云端处理 | 无需为这些操作连接相框，避免无意义耗电 |
| 自动转向与正常轮播 | 相框已有本地检测/绝对计划 | 沿用原本地规则 | 不经手机/BLE调用驱动，必须优先于管理工作 |

用户最新明确：服务器保持唯一设置来源，正常每轮唤醒取服务器设置参数的逻辑保持不变。禁止经 BLE 传朝向、轮播、作息或展示来源等设置，禁止建立独立本地配置副本。BLE 只携带“现在检查服务器”的触发意图，设备仍沿用原服务器状态/参数读取入口；新增显式触发不替代或改写原定时周期。网络凭据管理继续使用已确认的本地 BLE 配网路径。

建议统一增加单一“现在检查服务器”的本地指令，而不是让每个页面强行重启设备或各自模拟按键。用户提交→云端保存/建任务→BLE主人认证（不传设置参数）→设备排队，完成正在进行的屏幕操作→打开 Wi-Fi→拉取对应状态/任务→按真实设备阶段反馈；手机不在附近时保留云任务等待，页面明确说明“已保存/等待同步”，不得回滚已保存的云设置或宣称相框已经完成。管理会话不改变普通播放的准备截止点。

目前 Wi-Fi 管理已经实现，其余是本次实际代码排查得出的可改进清单，尚未接入通用即时执行。1505 已完成应用区安装、真实主人验证和公司现场 10 个 AP 的扫描/分页读取；轮播/转向及独立供电验收仍待进行。后续扩展不能抢占基本显示能力。
