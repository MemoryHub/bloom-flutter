## 用户交互

打开 App、首页、设备列表、详情、Wi-Fi 页只读缓存或云端摘要，不搜索/连接蓝牙。添加按钮进入独立 Wi-Fi 页面，依次显示连接相框、验证、获取网络列表、连接网络。删除先确认，再连接和执行；设备返回成功后更新列表。没有取名、第一张照片和四步向导。

连接结束、取消、后台和超时均释放。相框广播保持可发现；已有连接期间改为不可连接但可扫描的占用广播，两端展示“正在被其他手机操作”。占用来自真实广播，空扫描不伪造占用。

首次开箱仍是原四步流程。未配对且没有保存网络时只保留蓝牙，用户进入 Wi-Fi 步骤才打开 Wi-Fi 射频；已有网络的首次绑定、云端归属、首播与正常解绑继续保留。

首次绑定或另一台手机首次管理，需要手机联网取得并安装主人授权。以后使用本机安全存储中的凭证，Wi-Fi 添加/删除不请求服务器。相框是否能访问互联网不决定本地管理能否执行。

## 授权与网络写入

服务端只向当前主人返回加密保存的 P256 管理私钥。手机私钥保存在账号、设备分别隔离的安全存储；相框只接收公钥，以及云端 RSA2048 对设备 ID、现场挑战、授权代次和公钥摘要的签名。设备验证签名后持久保存公钥。日常用 P256 对新挑战签名，经原 Security1 加密通道本地验证。管理私钥不发给相框；制造 PoP 或旧二维码不能代替主人签名。

初始化授权与现场网络操作是不同阶段。迁移 `023_local_frame_admin.sql` 只新增授权列。正常解绑开始持久执行后撤销本地公钥；云端确认设备清理/欢迎刷新完成后移除主人及供图关系并清授权，保留所有云端照片。新主人使用更高代次及新密钥。

加入网络采用异步连接，真正连接目标 SSID 并得到 IP 后才保存。错误密码/写入失败保留原已保存网络。删除备用网络不切当前网络；删除当前配置先清掉驱动中的旧配置，再尝试其他已保存网络；删除最后一个仍可通过蓝牙添加。暂时关闭自动重连，结束后恢复原设置，避免重新连到刚删除的网络。

本地扫描由待机线程异步执行并分页读取，绑定后关闭原无主人授权的 `prov-scan`。请求继续原 100 字节分片；超过单包上限的返回数据使用 96 字节分片，绑定会话/请求/顺序及 30 秒上限，最长 2048 字节。状态包含多个长 SSID 也能完整返回。

## 轮播、转向和低功耗

待机保留同一个 ULP 方向程序，关闭其深睡停止分支，通过自动轻睡保留蓝牙。等待仍锚定绝对准备时刻，不由网络操作重算。到点优先执行正常周期；稳定转向在到点前执行，保留原准备截止点。配网扫描或连接可被中断，未成功的候选不会写入保存列表。转向入口显式关闭 Wi-Fi，继续只读当前缓存，不因管理页开过 Wi-Fi 而触发刷后联网。

保留工作阶段保护；只在真正管理网络时启用保护计时，普通长期待机不误触发。失败的低功耗/蓝牙初始化退回原深睡恢复，避免 CPU 长期忙转。

固定 Arduino **2.0.11** 和 ESP-IDF **4.4.5**，重新构建相同核心以启用 PM、Tickless、蓝牙 modem sleep、主晶振轻睡支持及 OPI PSRAM。没有修改已安装 Arduino SDK，没有升级 3.x，没有修改真实设备分区、bootloader 或 eFuse。制造 USB 准备窗口先执行，之后才启用新电源管理。

`python3 tools/build_ble_standby.py` 构建 `build/ble-standby/bloom_ble.bin`，版本 `20261015-ble-standby-v4B` / `2026101505`，默认依赖 `~/CProjects/toolchains/esp-idf-v4.4.5-bloom-ble`、`arduino-2.0.11-bloom-ble` 和 `idf44-bloom-py38-env`。工具检查 Git 精确版本及实际生成的低功耗配置，应用仍须小于原 1966080 字节槽。普通 `build.sh ota` 是保留深睡的诊断回退构建 `1501`，不能冒充常驻蓝牙版；`1500` 原源码须从基线取回。

## 实物启动中发现并修复的兼容问题

1502 候选的 NVS 首次初始化失败，先仅恢复应用，保持原分区和制造身份。只读诊断发现直接 Flash 读与缓存映射读不一致。DIO 配置对齐后问题仍存在；根因是复制的 Arduino SDK 配置关闭 `CONFIG_SPIRAM_BOOT_INIT`，独立 IDF 构建先初始化默认 Flash host，Arduino 随后初始化 OPI PSRAM 并重新校准 MSPI 时序，Flash host 仍使用旧时序。最终 profile 开启 SDK 早期 PSRAM 初始化，Arduino 源码避免二次初始化；实物诊断中直接/映射字节、NVS、排程和缓存读取均恢复。构建器检查早期初始化、DIO 宏及镜像头，原 bootloader/分区未改变。

另一个实物启动问题是 Wi-Fi 关闭时 Arduino 已反初始化驱动，官方 BLE 配网模块要求驱动先存在。`startBle` 在驱动关闭时先初始化，蓝牙服务就绪后待机再关闭 Wi-Fi 射频。新增测试直接执行生产启动函数，覆盖关闭驱动、初始化失败、重复调用和已有 RAM 配置保留。失败 1502 包已从活动交付目录移出。

用户最新约束：服务器保持朝向/轮播/作息/展示内容参数的唯一来源；保留每轮唤醒读服务器设置的逻辑。通用 BLE 扩展只应发送“现在检查服务器”的触发，不能下发设置或建立本地参数副本。这些扩展是已排查的待接入事项，详见独立清单。

主人认证的实物回归还发现 SDK 默认 BTC 任务 3072 字节栈不足：P256 验签进入硬件加密驱动时栈溢出。最终构建将其固定为 8192 字节，并在构建器检查实际配置，成功认证记录脱敏栈余量。

连接电脑时依据 USB SOF 判断主机是否活动，活动期间保留动态调频、关闭自动轻睡，以保证 USB 维护通道；拔除后在主循环恢复自动轻睡。该策略已覆盖 SOF 变化、750ms 失活、重接和计时回绕的主机回归。连接电脑的测试不代替独立充电器/电池下的常驻蓝牙、轮播、转向和整板电流实测。

扫描回归：原异步扫描使用 120ms/channel，使 Arduino 2.0.11 在 2400ms 后清除扫描 ownership；蓝牙共存下扫描事件迟到，guard 会拒绝消费，形成扫描失败。现使用 SDK 默认驻留时间，扫描期间通过状态位等待完成，独立 15 秒总上限；超时停止并释放。生产 poll 函数回归覆盖超过旧超时仍保留归属、完成结果、总超时及计时回绕。最终现场结果见验收 JSON。
